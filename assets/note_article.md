タイトル候補
- 貼り付けて走らせるだけ。AIにコード監査をやらせるプロンプト集を作った
- Claude Code / Codex に「セキュリティ監査」を丸投げするためのプロンプト集
- 毎回プロンプトを書くのをやめた。AIコード監査の型をリポジトリにした


本文ここから

AIエージェントにコードのセキュリティ監査をやらせたい。脆弱性もバグも保守性も見てほしい。ついでに、現行機能を壊さない範囲で直せるところは直してほしい。

やりたいことは毎回同じなのに、毎回プロンプトをゼロから書いていました。しかも書くたびに微妙に指示がブレる。「ビルドはするな」と書き忘れて勝手にコミットされかけたり、途中で「これ直していいですか？」と止まって放置されたり。

そこで、監査のやり方そのものをリポジトリに固めました。プロジェクトに依存しない、貼り付けて使える汎用テンプレートだけを置いたものです。

何ができるか

ツール（Claude Code / Codex CLI）と、対象がDBを持つかどうかで、最適な監査プロンプトを4種類用意しています。やることは共通で、セキュリティ・脆弱性・バグ・保守性の監査と、現行機能を壊さない範囲の修正です。

どのプロンプトも、同じ前提を必ず守るように作ってあります。

- ビルド・コミット・本番DB操作・抜本的な作り直しはしない
- 途中で止まらず、最後まで走り切る
- 人間の判断が要るところは、勝手に決めず記録してパスする

使い方は3ステップ

1. このリポジトリをクローンする。置き場所はどこでもよくて、特定のローカルパスに依存しません。

リポジトリはこちらです。
https://github.com/ishizakahiroshi/ai-audit-prompts

git clone https://github.com/ishizakahiroshi/ai-audit-prompts.git

2. 監査したいプロジェクトで、AIに次のように頼む。クローン先のパスを repo に読み替えてください。

Claude Code の場合は、repo/docs/README_activation.md を読んで、その自動選択ルールに従い、このリポジトリに最適な claude_ultracode 版の監査プロンプトを選んで、その中身どおりに実行して、DB区分は自動判定でいい、ultracode で、と頼みます。

ファイル名を直接指定しなくても、起動ルールがツールとDB区分から自動でプロンプトを選びます。末尾の ultracode は複数エージェントを並列で走らせるスイッチで、軽く済ませたいときは外します。

3. 毎回パスを書くのが面倒なら、対象プロジェクトの CLAUDE.md（Codex なら AGENTS.md）に合言葉を仕込んでおくと、「run audit」と言うだけで起動します。

なお、監査結果はあなたが話しかけた言語で返ります。英語で頼めば英語、日本語なら日本語でレポートが返るので、翻訳の手間はありません。

設計でこだわったところ

監査プロンプトは4ファイルに分かれていますが、全ファイルで絶対に表現がズレてはいけない不変条件を、別の1ファイルに正本としてまとめています。どれか1つを直したら、必ずそこと突き合わせて全部に反映する。地味ですが、監査の品質が4ファイル間でブレないための要です。

それと、このリポジトリには監査の進め方（メソッド）だけを置いています。認証情報やAPIキー、サーバー構成、顧客名、特定プロジェクトの調査メモやログは絶対にコミットしません。汎用テンプレート専用、という線引きを徹底しています。

まとめ

AIにコード監査をやらせる「型」を一度作ってしまえば、あとは貼り付けて走らせるだけになります。毎回プロンプトを考える時間と、指示のブレが消えました。同じことを繰り返している人の参考になればうれしいです。
