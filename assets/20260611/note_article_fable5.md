Claude Fable 5 に対応した監査プロンプトを追加しました。

先月、AIコード監査プロンプト集（Claude Code / Codex CLI 向け）を公開しました。今回はそこに Claude Fable 5 対応の2ファイルを加えた話です。

---

【IMAGE-1 をここに差し込む】

---

なぜ Fable 5 版が要るのか

もともとのプロンプト集には ultracode（Claude Code の多エージェント並列ワークフロー）と Codex CLI の2軸がありました。ultracode はエージェントを観点ごとに並列で走らせる設計で、広くカバーするのが得意です。

Fable 5 はそれとは性格が違います。並列で広げるより、1つのエージェントが拡張思考を使って深く掘るのが向いているモデルです。

---

【IMAGE-2 をここに差し込む】

---

具体的には、ultracode は「セキュリティ・バグ・依存関係・保守性をそれぞれ別のエージェントに担わせて同時に走らせる」という設計です。一方 Fable 5 は拡張思考が常時オンで、1つのエージェントが「これは本当に到達可能か」「既存のバリデーターで防がれていないか」と自分で深掘りしながら進みます。

「広く・速く」か「深く・根拠まで詰める」か、という違いです。コードベースが大きい場合は ultracode、複雑な認可ロジックや微妙なトランザクション境界を丁寧に見たい場合は Fable 5、という使い分けのイメージです。

使い方は3ステップ

---

【IMAGE-3 をここに差し込む】

---

1. Claude Code で /model claude-fable-5 と打ってモデルを切り替える

2. プロンプトを投げる

簡易版（引数省略・全デフォルトで動かす場合）:

<repo>/docs/README_activation.md を読んで、claude_fable5 版の監査プロンプトを選んで実行して。

強度ハイ・フルループ・全観点・リポジトリ全体のデフォルト値で動きます。DB区分も自動判定されます。まず全体を一通り見たいときはこれが最速です。

詳細版（対象を絞りたい場合の例）:

<repo>/docs/README_activation.md を読んで、claude_fable5 版の監査プロンプトを選んで実行して。
DB区分: あり
強度: ミッド
スコープ: 調査まで
観点: セキュリティ・脆弱性
対象: src/api/
除外: src/api/tests/

「認可まわりだけ深く見たい」「今日は調査だけで修正はしない」といった場合は引数で絞ります。スコープを「調査まで」にすると finding を報告して止まるので、まず問題の全体像だけ把握したいときに便利です。

3. あとは待つだけ。拡張思考が走り、finding の発見から修正まで一気にやり切ります。

注意点として、Fable 5 は1回のリクエストが数分に及ぶことがあります。タスクを投げたらしばらく待つ設計で使うのが合います。

ファイル構成

今回追加した2ファイルはこちらです。

claude_fable5_audit_db_app.md — DB（SQL/ORM/トランザクション）を使うアプリ向け
claude_fable5_audit_db_less_app.md — ファイル・設定・外部API中心のアプリ向け

既存の ultracode 版・Codex 版と同じ不変条件（ビルド禁止・コミット禁止・止まらず最後まで・判断待ちは記録してパス）を守る設計にしてあります。

Fable 5 ならではの設計ポイントは、強度の定義です。ultracode 版では「エージェントの並列数で強度を制御する」のに対して、Fable 5 版では「拡張思考でどこまで深く掘るか」で制御しています。ハイ強度では処理経路を追って根拠まで詰め、ローでは入力点と高リスク箇所だけに絞ります。
